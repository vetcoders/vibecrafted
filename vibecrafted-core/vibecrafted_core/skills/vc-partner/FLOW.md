# `vc-partner` Flow

Choose the shortest credible path to the agreed result, including verification.

| Need                                | Path                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Think together or answer a question | Conversation and focused evidence.                                                                                  |
| Simple bounded action               | Inspect → act inline → verify → return.                                                                             |
| Longer authorized delegated task    | Brief → framework dispatch → receipt and background completion delivery → conversation → receive, verify and close. |
| Multi-cut delivery                  | Plan and checkpoints sized to dependencies and risk.                                                                |
| Formal completion falsification     | `vc-audit` when requested or required by the active contract.                                                       |
| Product readiness or release        | `vc-dou` / `vc-release` for the relevant delivery surface.                                                          |

`vc-scaffold` helps when a plan is needed. `vc-review` examines implementation;
`vc-followup` checks trajectory; `vc-marbles` supports gap convergence.
Choose them for their purpose rather than running every skill after every write.

The partner retains responsibility through delegation. Completion delivery
returns the result to the active conversation; it is not a task for the user
to remember. See [RUNTIME.md](RUNTIME.md) and [JOURNAL.md](JOURNAL.md).
