# `vc-partner` Flow

Wybierz najkrótszą wiarygodną drogę do uzgodnionego wyniku, razem z weryfikacją.

| Potrzeba                                  | Droga                                                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Wspólne myślenie lub odpowiedź na pytanie | Rozmowa i potrzebne dowody.                                                                             |
| Proste, ograniczone działanie             | Poznaj stan → wykonaj inline → sprawdź → wróć.                                                          |
| Dłuższe autoryzowane zadanie delegowane   | Brief → dispatch frameworka → receipt i odbiór ukończenia w tle → rozmowa → odbierz, sprawdź i domknij. |
| Dowiezienie w kilku cięciach              | Plan i checkpointy dobrane do zależności i ryzyka.                                                      |
| Formalna falsyfikacja ukończenia          | `vc-audit`, gdy jest zlecony lub wymagany przez aktywny kontrakt.                                       |
| Gotowość produktu lub release             | `vc-dou` / `vc-release` dla właściwej powierzchni dowiezienia.                                          |

`vc-scaffold` pomaga, gdy potrzebny jest plan. `vc-review` sprawdza implementację;
`vc-followup` kierunek; `vc-marbles` pomaga domykać luki.
Dobieraj je do celu, zamiast uruchamiać wszystkie po każdym zapisie.

Partner zachowuje odpowiedzialność przez delegację. Odbiór ukończenia przywraca
wynik do aktywnej rozmowy; użytkownik nie musi o nim pamiętać.
Zobacz [RUNTIME.md](RUNTIME.md) i [JOURNAL.md](JOURNAL.md).
